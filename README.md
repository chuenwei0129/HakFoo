# HakFoo

小时候看动漫和武侠片，最燃的瞬间永远是角色出招前的那一声大喊。《龙珠》的"龟派气功"，《圣斗士》的"天马流星拳"，黄飞鸿的"佛山无影脚"——招式先有名字，动作才会被记住、被练习、被传承。

《成龙历险记》里的黑虎阿福把这件事推到极致。"乌鸦坐飞机""龙卷风摧毁停车场"这种先报名、再动手的劲儿，一直很打动我。所以这个仓库叫 **HakFoo**。

> 一个前端认知操作系统——把零散输入编译成可递归生长的知识系统。

## 架构

```text
输入层（吸收）→ 理解层（解构）→ 抽象层（模型）→ 输出层（重构）→ 实践层（代码）→ 沉淀层（知识库）→ 演化层（长期迭代）
```

## v1 Skills

| Skill | 作用 | 层 |
| --- | --- | --- |
| `fe-read` | 读博客、源码、RFC、文档，先给结构和热点 | 输入 |
| `fe-book` | 拆技术书骨架，抓作者的问题和框架 | 输入 |
| `fe-learn` | 从七个方向切透一个前端概念 | 理解 / 抽象 |
| `fe-plain` | 把复杂概念讲成人话，验证是否真的理解 | 理解 |
| `fe-note` | 重写旧笔记，压成知识单元 | 输出 / 沉淀 |
| `fe-code` | 给知识点做最小实验 | 实践 |

默认闭环：`旧笔记/博客/书/代码 → fe-read / fe-book → fe-learn / fe-plain → fe-note → fe-code`

## 知识单元标准

每条知识单元至少包含：

- `Title`：在解释什么
- `Problem`：解决什么压力
- `Model`：最小心智模型
- `Mechanism`：运行时发生了什么
- `Boundaries`：什么时候不成立
- `Connections`：和哪些相邻概念有关
- `Example Or Experiment`：代码入口或实验
- `Open Questions`：还没搞懂的地方

## 路由规则

- 旧笔记 → `fe-note`
- 说不清 → `fe-plain`
- 没追到底 → `fe-learn`
- 有结论没验证 → `fe-code`

## 沉淀节奏

- 每次读完至少沉淀一条 `fe-note`
- 每学一个机制补一个 `fe-code`
- 每周做一次知识压缩
- 每月更新知识地图（已掌握 / 知道但不会用 / 需要补实验）

## Wave 2 优先级

1. `fe-rank` — 抽象层，把一个领域压成最少生成器
2. `fe-qa` — 长期记忆，压成 Q-A 链
3. `fe-arch` — 工程层，读 repo 看边界和脆弱点
4. `fe-history` — 演化层，追溯框架替代了谁、牺牲了什么

之后再考虑：`fe-write`、`fe-map`、`fe-present`、`fe-push`

## 设计原则

- 有招必有名
- 技能不是一次性提示词，是可反复使用的认知动作
- 值钱的不是记住多少 API，而是能不能压缩、重写、验证、迁移
