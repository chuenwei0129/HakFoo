# plain：大白话解释

把复杂的东西说明白。就像你在给一个聪明的 12 岁孩子讲。

不规定怎么写。规定不能怎么写。下限锁死，上限放开。不同主题有不同的最佳写法——类比、故事、问答、递进的例子、一个长场景——由内容决定形式。

## 适用范围

这个 skill 最擅长：解释抽象概念、拆掉术语墙、讲清楚一个模型或原理。

不太适合直接套用的情况：
- **操作步骤多**（十几步流程）→ 可以拆成几段，每段用大白话讲清一步，但纯靠类比容易乱
- **数字密集**（一堆数据要对比）→ 换成排序、对比表或「谁大谁小」的口语表达
- **多方博弈**（A影响B，B影响C，C又反过来卡A）→ 用「两个人吵架，第三个人拉偏架」的故事可能比纯类比更清楚
- **争议问题**（两边的理由都成立）→ 改成正反方轮流说话，而不是硬找一个统一类比

遇到这些情况，核心规则（口语检验、零术语、短词优先）仍然要守，但工具箱里优先选：**好问题、故事、正反辩论、排序**，而不是硬靠类比。

## 红线（每条必须过，顺序即优先级）

1. *准确优先* — 大白话不是乱说。不能为了顺口把边界抹平，不能为了好懂把关键条件删掉。讲不准，就直接说哪里不确定
2. *口语检验* — 最高法则。读出声来，你会这样跟一个聪明的朋友说话吗？不会→改到会。连词不是敌人——"但是""所以"是思维转弯的声音，只砍机械连词（"此外""值得注意的是"）
3. *术语后置* — 聪明的 12 岁孩子能复述。能不用术语就先不用。专业词必须出现时，先用大白话把意思落地，再顺带提术语名
4. *短词优先* — 能用两个字说的不用四个字。「进行分析」→「看」。大词不让你显得聪明，只让人读得累
5. *一句一事* — 每句只推进一步。长句拆短
6. *具体* — 名词看得见，动词有力气。「有人觉得情况不太好」→「张三说项目要黄了」。形容词能砍就砍
7. *开头给理由* — 第一句话让人想读下一句。不铺垫、不背景、不「自古以来」
8. *不填充* — 删开场白、拐杖词、夸大象征。每句都在干活
9. *信任读者* — 跳过软化、辩解、手把手引导。说一遍够了
10. *诚实* — 想不清楚就说想不清楚。"大概 70%" 比"可能"诚实

## 工具箱（选用，不必全用）

写的时候可以从这里拿工具，没有哪个是必须的：

- *类比* — 找结构对得上的日常经验。好类比承重（去掉它文章塌），多层（挖一层还像），自明（不需要解释类比本身）。动词延伸到新对象时检查中文动宾搭配是否自然
- *好问题* — 找读者的卡点，变成问题。读者被卡住，才想往下读
- *裂缝* — 模型/类比在哪里不够？那个点往往最值钱。不宣布它，让读者自己感到
- *画面* — 闭眼能看到的场景。硬造的画面比没有更糟
- *故事* — 一个具体的人遇到一个具体的问题。读者跟着走
- *反问入链* — 遇到隐含前提，用问题打开，然后回答它
- *骨架图* — 概念涉及空间关系时，嵌入 ASCII 图

## 执行

### 1. 获取内容

URL → 先获取网页内容 | 文本 → 直接用 | 文件路径 → 先读取文件 | 概念 → 直接解释 | 书名/论文名/不确定事实 → 先查资料，再解释

如果用户的问题缺关键上下文，先补一个最必要的问题；如果可以合理假设，就带着假设继续，并把假设说清楚。

### 2. 写

形式自由。从工具箱里选最适合这个主题的方式，也可以不选——如果有更好的写法，用它。

输出默认是一篇从第一行流到最后一行的连贯文章。内容简单时，不用子标题。内容复杂时，可以用很少的子标题帮读者跟上，但不要写成提纲腔。

禁止：
- 生硬的流程标签和写作腔标签（`* 类比` / `* 裂缝` / `第一部分` / `接下来我们讨论`）
- 为了显得会写而插入和内容无关的元评论

### 3. 过红线

逐条扫红线清单。额外检查：

- 破公式——否定式排比全文不超过两处，三段式改两项或四项
- 变节奏——长短句交替，段落结尾多样
- 杀金句——听起来像可引用的，重写
- 查跳跃——每步逻辑可追？前句说 A，后句跳到 B→补桥
- 查译感——动宾搭配中文天然吗？不自然→换动词或换句式

扫完列修改清单（哪句触发什么，改前→改后）。清单不写入文件。

### 4. 生成 md 文件

只在用户明确要求保存时才写文件。默认直接输出到对话。

如果用户说"保存"、"写到文件"、"存下来"——用以下规范：

**命名**
- 时间戳：`date +%Y%m%dT%H%M%S`
- 文件名：`{时间戳}--{short-title}.md`
- 示例：`20260414_143022--neural-network-learning.md`

**存放位置**
- 有 `~/Notes/plain/` 就放这里
- 没有就放当前工作目录，或问用户放哪

**文件头**

```yaml
---
title: ""
source: ""        # URL/书名/论文名，如果有的话
created: ""       # 生成时间
summary: ""       # 一句话总结，方便以后检索
tags:
  - "plain"
  - ""           # 主题标签，如 "AI", "经济学"
---
```

**正文格式**
- 不包装在代码块里，直接写 Markdown
- 前面写的解释内容照原样放入，不加额外的"这是解释"类元评论

## 验收

- *答到了*：用户问的那个点，真的被回答了，没有只是在写一篇像解释的文章
- *不讲偏*：关键区别、条件、边界还在，没有为了顺口把意思压扁
- *真懂*：读完能用自己的话复述核心
- *零术语*：12 岁孩子能跟上
- *记得住*：读完脑子里留下了什么——一个画面、一个问题、一个转折，什么都行
- *想读完*：从头到尾没有想跳过的段落
