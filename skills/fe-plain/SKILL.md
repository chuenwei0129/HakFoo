# fe-plain

把一个难概念讲到“脑子里有图像，有抓手，能复述”。

## 什么时候用

在这些场景优先使用：

- 用户想听“人话版”
- 用户知道名词，但没有形成模型
- 你怀疑对方只是记住了术语，没有真正理解

## 不要用于

- CLI 或部署步骤
- benchmark、参数、数据对比
- 分布式一致性这类多角色复杂博弈

如果用户真正想追到底层机制，下一步更适合按 `fe-learn` 的工作方式展开。

## 工作方式

### 1. 从问题开始，不从定义开始

先讲：

- 没有这个机制时，会卡在哪里
- 为什么当时的人受不了

不要开头就背定义。

### 2. 术语后置

先让用户脑中出现画面，再给名字。

不要一上来就丢术语；等结构站稳后，再告诉用户“这就叫 X”。

### 3. 用可映射的类比

类比必须明确对应关系，而不是只求“像”。

至少说清：

- 现实世界里的什么
- 对应系统里的什么

### 4. 把精度补回来

类比讲完后，必须补一句：

- 这个类比在哪失效
- 真正的系统边界是什么

### 5. 压成一句真相

最后用一句很短的话把核心钉住，要求用户未来能复述出来。

## 输出格式

默认直接在对话里输出，优先使用这个骨架：

```markdown
## The Pressure
## First Intuition
## Analogy
## Real Mapping
## Where The Analogy Breaks
## One Sentence Truth
```

如果适合，再补：

```markdown
## Tiny Example
```

## 质量要求

- 准确优先，不为了顺口偷换概念
- 不幼态化，不把读者当小孩哄
- 类比必须有映射关系
- 必须写明类比的失效边界

## 结果分流

- 如果用户还想追到底层机制，下一步建议改用 `fe-learn`
- 如果用户已经懂了，想沉淀成长期笔记，下一步建议改用 `fe-note`

## 示例

**Example 1**

Input:

```text
用大白话讲清楚闭包
```

Expected shape:

- 从“函数走了，变量为什么还活着”切入
- 给一个可映射类比
- 说明类比会在哪些地方误导人
