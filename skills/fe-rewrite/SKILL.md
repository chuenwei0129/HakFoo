# fe-rewrite

## Purpose

```text
将零散、低结构、不可复用的技术内容：

- 重构
- 抽象
- 压缩
- 建立连接
- 转化为长期可生长知识
```

目标不是：

```text
“写得更好”
```

而是：

```text
“变成认知资产”
```

---

# Core Principles

## 1. 重写 ≠ 改写

不要只是：

```text
换一种说法
```

而是：

```text
重新建立知识结构
```

---

## 2. 信息必须可递归

输出必须满足：

```text
- 可引用
- 可组合
- 可拆分
- 可连接
- 可继续压缩
```

否则不算完成。

---

## 3. 永远优先“生成模型”

不要堆：

```text
API
细节
语法
```

而是提炼：

```text
运行机制
状态流
约束
调度
依赖关系
系统模型
```

---

## 4. 输出必须可验证

任何结论都应尽量包含：

```text
- 实验
- 代码
- 边界
- 反例
```

避免形成：

```text
“AI 幻觉知识”
```

---

# Input

支持输入：

```text
- 旧笔记
- 博客草稿
- 技术文章
- RFC
- 源码分析
- 项目经验
- 知识碎片
- 聊天记录
- 面试题
- issue / PR
```

---

# Rewrite Goals

rewrite 时优先做：

## 1. 去冗余

删除：

```text
- 情绪化表达
- 重复描述
- 无信息密度段落
- 无意义案例
```

---

## 2. 提取问题本质

回答：

```text
这个知识到底在解决什么问题？
```

---

## 3. 建立生成模型

例如：

不要写：

```text
React Fiber 是 React16 新架构
```

而是：

```text
Fiber 是一种可中断的增量协调调度模型
```

---

## 4. 建立连接关系

强制思考：

```text
它：
- 依赖什么
- 类似什么
- 会演化成什么
- 与哪些领域同构
```

---

## 5. 提炼长期有效思想

区分：

```text
- 时代实现
- 永恒思想
```

例如：

```text
Webpack 可能过时
但：

模块图
依赖分析
增量编译
不会过时
```

# Rewrite Strategy

## 情况 1：旧笔记很乱

优先：

```text
整理结构
```

不要急着“深度抽象”。

---

## 情况 2：已经有一定结构

优先：

```text
抽象生成模型
```

---

## 情况 3：源码分析类

优先：

```text
调用链
数据流
控制流
模块职责
```

---

## 情况 4：工程经验类

优先：

```text
模式
反模式
trade-off
失败案例
```

---

# Important Rules

## Rule 1

不要写成：

```text
教程
```

而应该写成：

```text
认知结构
```

---

## Rule 2

不要过度追求“完整”。

优先：

```text
可生长
```

---

## Rule 3

不要沉迷细节。

优先：

```text
生成细节的规则
```

---

## Rule 4

如果一个知识不能压缩：

```text
说明还没真正理解。
```

---

# Preferred Style

风格偏向：

```text
- 高信息密度
- 强结构
- 少废话
- 偏系统
- 偏工程
- 偏本质
```

避免：

```text
- 鸡汤
- 情绪化
- 口语废话
- 大段历史故事
- API 文档式写法
```

---

# Examples

## Bad

```text
React Fiber 是 React16 的新特性。
它可以提升性能。
```

---

## Good

```text
Fiber 本质是：

把不可中断的递归协调过程，
改造成：

可暂停、可恢复、可分优先级的增量调度系统。
```

---

## Bad

```text
Proxy 可以代理对象。
```

---

## Good

```text
Proxy 本质是：

JavaScript Runtime 层的对象操作拦截器。
```

---

# Final Goal

最终目标：

```text
把：

输入的信息

↓

变成：

可递归生长的长期认知资产。
```

而不是：

```text
“整理过的笔记”
```
